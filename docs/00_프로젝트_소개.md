# 00 · 이 프로젝트는 무엇인가

> 2026-08-05. **디자인 목업을 그리거나, 프로젝트에 새로 합류할 때 먼저 읽는 문서.**
> 무엇을 만들고 있고, 왜 만들고, 지금 어디까지 왔고, 화면에 나오는 용어가 무슨 뜻인지를 담았다.

---

## 1. 한 문장

**프롬프트 하나를 넣으면, 언어 모델(LLM)이 다음 단어를 고르기까지 내부에서 벌어지는 일 전부를 눈으로 볼 수 있게 만드는 웹 플랫폼.**

슬로건: *"블랙박스를, 들여다볼 수 있는 유리 상자로."*

## 2. 왜 만드나

AI 모델은 답을 내놓지만 **왜 그 답이 나왔는지는 아무도 보여주지 않는다.** 비전공자는 원리를 배울 방법이 없고, 실무자조차 "이 모델이 지금 뭘 하고 있는지"를 설명하기 어렵다.

교과서 그림이 아니라 **실제로 돌아가는 모델의 실제 숫자**를 보여주면, 그 간극이 메워진다. 이 도구는 그걸 목표로 한다.

- **교육**: AI를 처음 배우는 사람이 "토큰 → 층 → 확률"의 흐름을 눈으로 따라간다
- **실무**: 엔지니어가 모델의 확신도·주의 집중·이상 활성을 진단한다

## 3. 무엇이 다른가

| | Transformer Explainer (Georgia Tech) | 3dNN Visualiser | **본 프로젝트** |
|---|---|---|---|
| 프롬프트 입력 → 실시간 | O | X (구조만 정적) | **O** |
| 원하는 모델 지원 | X (GPT-2 고정) | O | **O (0.5B~32B 실증)** |
| 시각화 차원 | 2D | 3D | **3D** |
| 한국어 | X | X | **O (형태소 단위 지원)** |
| 용도 | 교육 | 구조 확인 | **교육 + 실무 진단** |

빈자리는 **"임의 모델 + 실시간 + 3D + 한국어"** 조합이고, 이 프로젝트는 정확히 거기에 들어간다.

## 4. 지금까지 만든 것 (전부 실측 검증됨)

### 추출 엔진 (Step 1, 완료)
모델 내부에서 **7종 신호**를 추론 1회로 캡처한다 — logits, surprisal, hidden state, embedding, attention, logit-lens, MLP 활성. 모델 4종(0.5B~14B, 3개 계열) × 7신호 = **21/21 검증 통과**. 파생 진단 지표 8종, 한국어 220쌍 테스트 배터리.

### 2D 플랫폼 (Step 2, 동작 중)
프롬프트 입력 → 1회 추론 → 화면 갱신. 세 화면으로 구성:
- **흐름**: 토큰 → 임베딩 → 층 → 확률의 좌→우 흐름, attention 곡선
- **토큰 벡터**: 단어 하나의 실제 숫자(수천 개), 의미가 가까운 단어, 층별 이동 궤적
- **패널**: 놀람도·attention·확신도·토큰 비용 등 진단 9종

### 클라우드 GPU 서빙 (실증 완료)
같은 플랫폼을 A100 80GB에 통째로 올려 **Qwen3-32B(64층)까지 실시간 분석** 확인. 토큰 인증 + 비동기 모델 로드 구현.

### 실측 수치 (같은 문장 "대한민국의 수도는")

| 모델 | 층 | 다음 단어 예측 | 분석 시간 |
|---|---|---|---|
| Qwen2.5-0.5B | 24 | 서울 10% (망설임) | 0.7초 |
| Ministral-3-14B | 40 | **서울 52.8%** | 2.6초 |
| Qwen3-32B | 64 | 어디 64.6% (질문으로 이어씀) | 초 단위 |

→ **크기는 확신을 바꾸고, 정렬(instruct 학습)은 스타일을 바꾼다** — 이런 걸 눈으로 보여주는 게 이 도구의 존재 이유.

## 5. 3D가 추가해야 하는 것 (Step 3, 지금 설계 중)

2D는 **검증용 프로토타입**이었고, **3D가 최종 제품**이다. 2D는 저사양·WebGL 미지원 환경의 폴백(평면 보기)으로 남는다.

3D가 보여줘야 하는 것은 "층을 쌓아놓은 예쁜 그림"이 아니라 다음 세 가지다:

1. **정보가 이동하는 경로** — 어떤 단어가 어떤 단어를 참고했는가
2. **깊이 방향으로 판단이 형성되는 진행** — 몇 번째 층에서 답이 정해졌는가
3. (여유 시) **attention과 MLP의 역할 분담** — 정보를 나르는 곳과 계산하는 곳

## 6. 화면에 나오는 용어 (목업 그릴 때 필요한 최소 사전)

| 용어 | 뜻 | 화면에서 |
|---|---|---|
| **토큰** | 모델이 읽는 조각. 단어보다 작을 수 있음 ("대한민국"이 대/한/민/국으로 쪼개지기도) | 문장이 칩으로 분해된 모습 |
| **층 (Layer)** | 계산 단계. 0.5B는 24개, 32B는 64개 | 세로로 쌓이는 축, 층 선택 UI |
| **임베딩** | 단어가 숫자 벡터로 바뀐 최초 상태 (문맥 섞이기 전) | 맨 아래 층 |
| **attention** | 한 토큰이 다른 토큰을 얼마나 참고하는지의 비율 (합=1) | 토큰 사이를 잇는 곡선, 진할수록 많이 봄 |
| **attention sink** | 볼 게 없을 때 첫 토큰에 주의를 버리는 현상. **의미 없음** | 점선으로 강등 표시 (착시 방지) |
| **MLP** | attention이 모아온 정보를 계산·가공하는 부분 | 층 안의 두 번째 단계 |
| **surprisal (놀람도)** | 모델이 그 단어에 얼마나 놀랐는지 (bits) | 토큰 배경색, 진할수록 예상 밖 |
| **logit-lens** | 중간 층에서 "지금 답한다면 뭐라고 할까"를 엿본 것 | 층별 중간 예측 라벨 |
| **결정 깊이** | 최종 답이 처음 확정되는 층. "여기서 답이 정해졌다" | 그 층부터 색이 굳는 연출 |
| **엔트로피** | 확신도. 낮으면 확신, 높으면 망설임 | 게이지 수치 (bits) |
| **차원 (d_model)** | 단어 하나를 표현하는 숫자 개수 (0.5B=896, 14B=5120) | 벡터 막대 그래프 |

## 7. 디자인 원칙 (이미 확정, 3D에도 그대로)

전문 도구답고 **"AI가 자동 생성한 화면"처럼 보이지 않는 것**이 목표다.

1. **카드가 아니라 지면** — 둥근 박스로 감싸지 말고 여백과 1px 선으로 나눈다
2. **비대칭이 기본** — 중앙 정렬 금지
3. **UI는 무채색, 색은 데이터에게** — 강조색(바이올렛 #4B31C8)은 한 화면에 대상 1개만
4. **라벨은 벌거벗는다** — 알약·뱃지 금지, 텍스트와 위치로 위계를 만든다
5. **범례 대신 주석** — 축 제목·범례 상자 대신 데이터 옆에 직접 설명 한 줄
6. **수치에는 항상 의미 문장** — "0.966" 옆에 "1에 가까울수록 거의 안 변했다는 뜻"
7. **데이터는 도착한다** — 분석 완료 시 순차적으로 등장, 곡선은 그려지고 숫자는 세어 올라간다

색·폰트·간격은 이미 토큰으로 정의돼 있다 (`web/css/tokens.css`): 배경 웜 페이퍼 #FCFBF9, 잉크 #14151A, 강조 #4B31C8, 제목 Wanted Sans, 본문 Pretendard, 수치 JetBrains Mono.
